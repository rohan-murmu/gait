Finds the exact agent edit that broke your tests.

Your agent edited forty files in twenty minutes. Then a test failed. gait checkpoints every edit off to the side and bisects them to find the one that broke it — with the file and the patch.

Get started How it works

Requires an existing git repo, Node ≥ 20 and git ≥ 2.43.

The problem

Git already solved this.
It just can't see what your agent did.

git bisect run is an excellent binary search. But it searches commits, and an agent produces edits. Three things follow, and each one is fatal on its own.

01

A session makes zero commits

Twenty minutes of work is one dirty working tree. Bisect has nothing to search.

02

Bisect rewrites your working tree

Every step checks out a different commit. Run it while an agent is working and you corrupt the agent's world.

03

A bad question still gets an answer

A repro command that fails everywhere, passes everywhere, or isn't installed still makes bisect print a confident, wrong sha.

How it works

Three things git can't do alone

gait does not reimplement binary search. The checkpoint chain is ordinary commits with ordinary parents, so git bisect run walks it natively.

01

The states to search

A checkpoint after every edit, written as a real commit object under refs/gait/checkpoints/ — never on your branch.

  • Invisible to git log, status and every branch
  • Built through a throwaway index, so it can't race the agent
  • Ref-reachable, so gc won't collect it
02

Somewhere safe to search

The bisect runs in a throwaway worktree in /tmp. Bisect state is per-worktree, so your checkout never learns it happened.

  • The agent keeps editing while the search runs
  • Dependencies symlinked in — no install per step
  • Worktree and its state torn down after
03

An honest answer

Three preconditions are checked before searching. When one fails, gait names it instead of returning a sha it can't stand behind.

  • Fails at the newest checkpoint — or there's no failure
  • Passes at the oldest — or the break predates the session
  • Missing command aborts, never blames a commit
The search

O(log n) test runs, not O(n) file reads

Twenty-one checkpoints resolve in seven runs — two pre-flight checks and five halvings. The agent gets one file and one hunk instead of a forty-file diff.

Architecture

Two shells over one core

The core never prints and never knows which shell called it. Every operation returns a discriminated union, so the agent and you can never be shown different answers to the same question.

MCP is the knowledge surface

Four read-shaped tools the agent pulls when it needs them. restore is deliberately not exposed — rolling back the working tree is your decision, not the agent's.

Observation never blocks

The checkpoint hook sits on the agent's critical path with a 10-second timeout. A slow gait degrades to no gait, never to a stalled agent.

⚠ What these numbers do not show

Flaky tests are unmeasured. Binary search assumes a deterministic oracle. A test that fails 10% of the time breaks monotonicity, and gait will give a confident wrong answer with no indication anything went wrong.
Binary search correctness was never in doubt. Given a deterministic oracle, bisect is correct by construction. The benchmark measures cost reduction, not whether the algorithm works.
The regressions are injected, not harvested. They're modelled on real mistakes, but a benchmark built from real bug corpora replayed as sessions would be stronger.
Compiler errors are a loss, not a win. gait took 16s to reach a file tsc named instantly. The tool tells the agent not to call it for those.
Install

Two commands and you're done

1 — Install from source

git clone https://github.com/rohan-murmu/gait.git
cd gait && npm install && npm link

The only supported install today — no Homebrew tap, no published npm package yet. Needs Node ≥ 20 and git ≥ 2.43.

2 — Wire it into your repo

cd your-repo
gait init --test "npm test"

Writes gait.json, registers the MCP server, documents the tool in CLAUDE.md, and installs the hook that checkpoints after every edit. The hook is the load-bearing piece — it makes the data exist without anyone remembering to ask.

Then, when something breaks: gait why --repro "npx vitest run src/auth.test.ts" — or let the agent call gait_find_breaking_change itself.
